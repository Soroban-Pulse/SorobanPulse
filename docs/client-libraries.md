# Client Libraries

Soroban Pulse ships generated/maintained client SDKs for three languages,
checked into the repo under `sdk/`:

| Language | Path | Source |
|---|---|---|
| Go | [`sdk/go/`](../sdk/go/) | Hand-written (no external dependencies, wraps the standard library `net/http`) |
| Python | [`sdk/python/`](../sdk/python/) | Generated by [OpenAPI Generator](https://openapi-generator.tech) 7.21.0 |
| TypeScript | [`sdk/typescript/`](../sdk/typescript/) | Generated by OpenAPI Generator 7.21.0 |

Only Python and TypeScript are generated from `openapi.json` — the Go SDK
predates codegen for this project and is maintained by hand (see
`sdk/go/client.go`, `sdk/go/retry_policy.go`). There is no `.openapi-generator`
marker directory under `sdk/go/`, confirming it isn't produced by the same
pipeline as the other two.

## Installation

Each SDK has its own README with full installation and usage instructions —
this doc does not duplicate them:

- **Go**: see [`sdk/go/README.md`](../sdk/go/README.md#installation) —
  `go get github.com/soroban-pulse/client-go`
- **Python**: see [`sdk/python/README.md`](../sdk/python/README.md#installation--usage) —
  `pip install` from the package directory or a git URL (it is not currently
  published to PyPI)
- **TypeScript**: see [`sdk/typescript/README.md`](../sdk/typescript/README.md#installation) —
  `npm install` from the package directory (not currently published to npm)

## Regenerating the SDKs

The Python and TypeScript SDKs are regenerated directly from the live OpenAPI
spec via the `generate-sdk` Makefile target:

```bash
make generate-sdk
```

This expands to:

```bash
# 1. Regenerate openapi.json from the #[utoipa::path] annotations on the
#    handlers (see docs/api-guide.md for how the spec is produced)
cargo run --bin gen_openapi > openapi.json

# 2. TypeScript client (typescript-fetch generator)
npx @openapitools/openapi-generator-cli generate \
  -i openapi.json \
  -g typescript-fetch \
  -o sdk/typescript \
  --additional-properties=typescriptThreePlus=true,supportsES6=true

# 3. Python client (httpx-based)
npx @openapitools/openapi-generator-cli generate \
  -i openapi.json \
  -g python \
  -o sdk/python \
  --additional-properties=library=httpx
```

The exact generator version (`7.21.0`) is pinned in the root
[`openapitools.json`](../openapitools.json), so `npx @openapitools/openapi-generator-cli`
picks up a consistent version without needing it installed globally.

The Go SDK is **not** part of this target — changes to `sdk/go/` are made by
hand and should be kept in sync with the REST surface manually.

> **Known gap**: at the time of writing, the checked-in `openapi.json` only
> documents 13 of the ~200+ routes registered in `src/routes.rs`'s `ApiDoc`
> (run `cargo run --bin gen_openapi | python3 -c "import json,sys; print(len(json.load(sys.stdin)['paths']))"`
> to check the current count). Regenerating the SDKs today would produce
> clients with far broader endpoint coverage than what's committed. See
> `docs/api-guide.md` for more on this discrepancy.

## Retry and backoff behavior

All three SDKs implement automatic retry with exponential backoff for
transient failures (`429`, `500`, `502`, `503`, `504`, and connection
errors), matching the guidance in [`docs/api-usage.md`](api-usage.md#rate-limiting).
Defaults and configuration differ slightly per language — see each SDK's own
doc rather than re-deriving it here:

- **Go**: no separate file; documented inline in
  [`sdk/go/README.md`](../sdk/go/README.md) under "Retry Configuration" /
  "Retry Policies", and implemented in
  [`sdk/go/retry_policy.go`](../sdk/go/retry_policy.go).
- **Python**: [`sdk/python/RETRY_AND_BACKOFF.md`](../sdk/python/RETRY_AND_BACKOFF.md)
- **TypeScript**: [`sdk/typescript/RETRY_AND_BACKOFF.md`](../sdk/typescript/RETRY_AND_BACKOFF.md)

All three default to the same backoff sequence used elsewhere in the project
docs: `1s, 2s, 4s, 8s, 16s`.

## Which one should I use?

| Need | Recommendation |
|---|---|
| No external dependencies, small binary | Go SDK |
| Data science / scripting, async support via `httpx` | Python SDK |
| Browser or Node.js, full type safety | TypeScript SDK |
| Language not listed here | Use `openapi.json` directly with your own OpenAPI Generator invocation, or plain `curl` (see [`docs/api-usage.md`](api-usage.md)) |

See [`docs/sdk-integration-guide.md`](sdk-integration-guide.md) for
per-language quickstarts, authentication wiring, and streaming examples.

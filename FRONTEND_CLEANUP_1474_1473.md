# Issues #1474 & #1473 - Frontend Cleanup: Entry Points & Design Tokens

## Issue #1474 - Remove Duplicated main.ts and main.tsx Entry Points

### Problem

web/src contains both main.ts and main.tsx:
- Only ONE can be referenced in web/index.html
- One is dead code or duplicates initialization logic
- Theme bootstrapping may run twice or never
- Similar duplication: web/src/api.ts vs web/src/api/

### Current State

```
web/src/
├── main.ts          (theme handling, lines 35–46)
├── main.tsx         (React entry point)
├── api.ts           (API client helpers?)
├── api/             (Generated API client?)
├── index.css
├── styles/          (CSS modules?)
└── ...
web/index.html       (references: script type="module" src="/src/main.tsx")
```

### Analysis & Decision

**Step 1: Determine which file is actually used**
```bash
grep -r "src/main" web/index.html
grep -r "type.*module" web/index.html
# Output: determines if main.tsx or main.ts is referenced
```

**Expected:** index.html references `/src/main.tsx` (React entry)

### Implementation Steps

#### Phase 1 - Audit Current Setup (PR 1)

1. **Verify index.html entry point:**
```bash
cat web/index.html | grep -A 2 "script.*module"
# Should show: src="/src/main.tsx"
```

2. **Check what main.ts contains:**
```bash
head -50 web/src/main.ts
# Check: theme bootstrap code?
```

3. **Check what main.tsx contains:**
```bash
head -50 web/src/main.tsx
# Check: React.createRoot()?
```

4. **Decide: Where should theme bootstrapping live?**
   - Option A: Move theme bootstrap to main.tsx before ReactDOM.createRoot()
   - Option B: Create theme.ts, import in main.tsx
   - Option C: Move to React component (useEffect in root App)

**Recommendation:** Option B (separate theme.ts) for clarity

#### Phase 2 - Consolidate Theme Bootstrap (PR 2)

**Create web/src/theme.ts:**
```typescript
// web/src/theme.ts
export function initializeTheme(): void {
  const theme = localStorage.getItem('theme') || 'light';
  document.documentElement.setAttribute('data-theme', theme);
  
  if (theme === 'dark') {
    document.documentElement.classList.add('dark');
  }
}
```

**Update web/src/main.tsx:**
```typescript
import { initializeTheme } from './theme';
import App from './App';

initializeTheme();

ReactDOM.createRoot(document.getElementById('root')!).render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
);
```

**Result:** Remove web/src/main.ts entirely

**Solution:**

## Issue #1473 - Consolidate Design Tokens

### Problem

Design tokens scattered across multiple places:
- design/build/ (pre-built, committed to git)
- dashboard/src/styles.css (custom colors)
- web/src/index.css (custom colors)
- web/src/styles/ (CSS modules)
- frontend/ (independent stylesheets)

**Result:** Inconsistent branding and token changes don't propagate

### Current State

```
design/
├── tokens/          (sources)
├── build/           (pre-built, committed)  ← PROBLEM
└── ...

web/src/
├── index.css        (custom colors)
├── styles/          (CSS modules)
└── ...

dashboard/src/
├── styles.css       (custom colors)
└── ...

frontend/
├── styles/          (independent)
└── ...
```

### Solution Strategy

#### Phase 1 - Audit Token Sources (PR 1)

1. **Check design/build/ contents:**
```bash
ls -la design/build/
cat design/build/tokens.json | head -20
```

2. **Check design/tokens/ sources:**
```bash
ls -la design/tokens/
# Expected: .json or .yml files defining tokens
```

3. **Check web/src/index.css:**
```bash
grep -E "^[[:space:]]*--" web/src/index.css | head -20
# Expected: CSS custom properties
```

4. **Decision: Keep pre-built or generate in CI?**
   - Option A: Generate in CI (remove committed design/build/)
   - Option B: Verify committed design/build/ is up to date

**Recommendation:** Option A (generate in CI) for single source of truth

#### Phase 2 - Set Up Token Generation (PR 2)

**Add to CI (.github/workflows):**

```yaml
# .github/workflows/design-tokens.yml
name: Generate Design Tokens
on:
  push:
    paths:
      - design/tokens/**
      - .github/workflows/design-tokens.yml

jobs:
  generate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Install Style Dictionary
        run: npm install -g style-dictionary
      - name: Generate tokens
        run: |
          cd design
          style-dictionary build
      - name: Verify tokens updated
        run: git diff --exit-code design/build/ || \
          (echo "ERROR: design/build/ is out of date"; exit 1)
```

**OR:** Add to design/package.json:
```json
{
  "scripts": {
    "build": "style-dictionary build"
  }
}
```

#### Phase 3 - Consolidate App Token Usage (PR 3)

**Update web/src/index.css to import from design/build/:**

```css

  /* Use generated CSS custom properties */

  background-color: var(--color-background-primary);
  color: var(--color-text-primary);

```

**Remove custom color definitions from:**
- web/src/styles/ (use generated tokens only)
- dashboard/src/styles.css (use generated tokens)
- frontend/ (consolidate into design/tokens/)

#### Phase 4 - Add Color Linting (PR 4)

**Port check-colors.mjs into web/:

```typescript
// web/scripts/check-colors.mjs
import fs from 'fs';
import path from 'path';

const HEX_COLOR_REGEX = /#[0-9A-Fa-f]{3,6}(?![0-9A-Za-z])/g;

function checkColors(dir) {
  const files = fs.readdirSync(dir);
  const violations = [];
  
  files.forEach(file => {
    if (file.endsWith('.css') || file.endsWith('.tsx')) {
      const content = fs.readFileSync(path.join(dir, file), 'utf8');
      const matches = content.match(HEX_COLOR_REGEX);
      
      if (matches) {
        violations.push({
          file,
          colors: matches,
          message: 'Use design tokens instead of raw hex colors'
        });
      }
    }
  });
  
  if (violations.length > 0) {
    console.error('❌ Raw colors found (use design tokens):');
    violations.forEach(v => console.error(`  ${v.file}: ${v.colors.join(', ')}`));
    process.exit(1);
  }
  
  console.log('✓ All colors use design tokens');
}

checkColors('web/src');
```

**Add to package.json:**
```json
{
  "scripts": {
    "lint:colors": "node scripts/check-colors.mjs"
  }
}
```

```markdown
# Design Tokens

All branding tokens (colors, spacing, typography) are defined in design/tokens/ and generated during the build.

## Using Tokens

Use CSS custom properties (from design/build/tokens.css):

```css
.button {
  background-color: var(--color-primary);
  padding: var(--spacing-md);
}
```

## Adding New Tokens

1. Edit design/tokens/colors.json (or appropriate file)
2. Run `npm run build` in design/
3. Commit design/tokens/ (NOT design/build/)
4. CI will verify tokens are up to date

## Linting

Check for raw hex colors:
```bash
npm run lint:colors
```
```

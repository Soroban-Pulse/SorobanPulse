## #1467 - Consolidate Notification Subsystem [STRATEGY]

### Current State
Notification logic spread across modules:
- `notification_admin`, `notification_batching`, `notification_channel`, `notification_dedup`
- `notification_delivery`, `notification_formatter`, `notification_rate_limit`
- Per-channel: email, sms, push_notification, slack, teams, telegram, discord, pagerduty, webhook, eventbridge, sqs

### Issues
- ✗ Only Discord uses SSRF guard
- ✗ Retry policies per-notifier (no consistency)
- ✗ Each channel re-implements rate limiting

### Recommended Pipeline
```
Message Input
    ↓
[notification_formatter] - Format by channel type
    ↓
[notification_dedup] - Deduplicate
    ↓
[notification_rate_limit] - Apply global rate limits
    ↓
[notification_channel] - Route to channel handler
    ↓
[channel_handler] - Channel-specific logic
    ├─ [ssrf_guard] - SSRF validation (all channels)
    ├─ [retry_policy] - Unified retry (all channels)
    ├─ [delivery] - Send via channel
    └─ [eventbridge/sqs] - Publish event
    ↓
[notification_delivery] - Track delivery status
    ↓
[notification_admin] - Admin logging/alerting
```

### Next Steps
1. Create unified `notification_pipeline.rs` module
2. Extract common patterns (SSRF, retry, rate limit)
3. Migrate channels one-by-one to pipeline
4. Deprecate old per-channel implementations
